1. ROOT CAUSE
--------------------------------------------------------------------------------
The seed script (`prisma/seed.ts`) contained a hardcoded static bcrypt hash:
'$2b$10$EpRnTzVlqHNP0.fKb.8Qe.O.z0l4.uW5b8R3lA8qJ0/V01J5KxX1G'

This hash did not match the plaintext development password string 'AdminPass123!'. 
As a result, when bcrypt.compare() evaluated the submitted password against the database 
record, verification failed, causing POST /api/auth/admin/login to reject valid credentials 
with HTTP 401 Unauthorized ('Invalid credentials').

2. FILES CHANGED
--------------------------------------------------------------------------------
- prisma/seed.ts
  * Added ES module import for 'bcryptjs' package.
  * Replaced static invalid hash string with dynamic bcrypt.hashSync('AdminPass123!', 10) calculation.

3. EXACT FIX
--------------------------------------------------------------------------------
In prisma/seed.ts:
- Replaced hardcoded password hash string with:
  const adminPasswordHash = bcrypt.hashSync('AdminPass123!', 10);
- Generated dev admin user record with passwordHash: adminPasswordHash.
- Database admin password record was updated with a valid bcrypt hash corresponding to 'AdminPass123!'.

4. DATABASE CHANGES
--------------------------------------------------------------------------------
- Targeted update applied to existing 'admin' record in PostgreSQL table 'admins'.
- Existing events, students, attendance records, and database tables were safely preserved without wiping or running 'prisma migrate reset'.
- Re-seeding (`npx prisma db seed`) now deterministically generates a valid bcrypt hash for the development admin user.
