1. PHASE GOAL
--------------------------------------------------------------------------------
Build the admin-side interface and backend API for viewing, filtering, and reviewing student 
attendance submissions and proof photos for university events without introducing manual data editing 
or altering existing attendance logic.

- Frontend Event Pages & Components (`apps/web/src/app/events/[id]/page.tsx`, `EventCard.tsx`)

4. API ENDPOINTS ADDED
--------------------------------------------------------------------------------
- GET /api/events/:eventId/attendance
  * Protected with JwtAuthGuard & RolesGuard('ADMIN').
  * Queries event details, attendance records joined with student profile, and computes summary metrics.
  * Returns JSON payload containing event details, summary breakdown, and records array.

5. ADMIN UI ADDED
--------------------------------------------------------------------------------
- Admin Event Attendance Management Page (/admin/events/[id]/attendance):
  * Admin Authentication Modal: Handles token input/login prompt when unauthenticated.
  * Header Banner: Displays Event Title, Date, Time Range, Location, Target Group, and navigation links.
  * Summary Metric Cards: Total Records, COMPLETED count, INCOMPLETE count, Check-In vs Check-Out breakdown.
  * Filter Bar: Real-time status filter (ALL / COMPLETED / INCOMPLETE) and search box (Student ID, Name, Faculty, Major).
  * Attendance Table: Columns for Student ID, Name, Faculty & Major, Year, Check-In time, Check-Out time, Status badge, and Inspect button.
  * Submission Inspection Drawer/Modal: Popup modal displaying student profile metadata, Check-In timestamp + photo proof, 
    Check-Out timestamp + photo proof, student feedback text, and status badge.

6. ATTENDANCE SUMMARY IMPLEMENTATION
--------------------------------------------------------------------------------
Summary statistics are dynamically computed on the backend:
- `totalRecords`: Count of all attendance records for the event.
- `completedCount`: Count of records with status = COMPLETED.
- `incompleteCount`: Count of records with status = INCOMPLETE.
- `checkedInCount`: Count of records where checkInTime !== null.
- `checkedOutCount`: Count of records where checkOutTime !== null.

7. FILTERING IMPLEMENTATION
--------------------------------------------------------------------------------
- Client-side status filtering: Users can toggle between ALL, COMPLETED, and INCOMPLETE.
- Search query filtering: Live search matches student ID, full name, faculty, and major strings.

8. SECURITY / AUTHENTICATION BEHAVIOR
--------------------------------------------------------------------------------
- Backend endpoint `GET /api/events/:eventId/attendance` is protected with `@UseGuards(JwtAuthGuard, RolesGuard)` and `@Roles('ADMIN')`.
- Unauthenticated requests are rejected with HTTP 401 Unauthorized.
- Proof photos are served safely via backend handler `/api/attendance/uploads/proofs/:filename` without exposing local filesystem paths.
- No sensitive admin password hashes, JWT secrets, or internal database metadata are exposed.

9. DATABASE CHANGES

- `prisma migrate reset` was NOT executed.
- Single record per `studentId + eventId` relationship maintained.
