1. PHASE & OBJECTIVE
-------------------------------------------------------------------------------
Phase: Phase 16.3 — Admin UI, Authentication & Navigation Separation
Objective:
  Separate public student attendance submission from administrator management tools.
  Implement a dedicated admin login page (`/admin/login`), an admin dashboard (`/admin`),
  protect all admin routes with token redirection, and eliminate user confusion on public
  event pages regarding student vs. administrator attendance.

-------------------------------------------------------------------------------
2. PROBLEM FOUND
-------------------------------------------------------------------------------
1. Unauthenticated users accessing `/admin/login` received a Next.js 404 error because
   no page component existed under `apps/web/src/app/admin/login/page.tsx`.
2. Admin authentication was previously handled via an inline modal overlay embedded inside
   the event attendance page (`/admin/events/[id]/attendance`), leading to confusing UX.
3. The public Event Detail page (`/events/[id]`) displayed an "Attendance" button pointing
   to the admin attendance management console (`/admin/events/[id]/attendance`), which misled
   students into attempting student attendance check-ins through admin tools.

5. AUTHENTICATION FLOW
-------------------------------------------------------------------------------
1. User visits `/admin` or `/admin/events/[id]/attendance`.
2. Frontend checks `localStorage.getItem('admin_access_token')`.
3. If token is missing, user is redirected to `/admin/login`.
4. At `/admin/login`, user submits admin credentials (`username`, `password`).
5. Frontend calls `POST /api/auth/admin/login`.
6. API returns JWT token (`accessToken`).
7. Token saved to `localStorage.setItem('admin_access_token', token)`.
8. User redirected back to `/admin` or target admin page.
9. Clicking "Sign Out" removes `admin_access_token` and redirects to `/admin/login`.
