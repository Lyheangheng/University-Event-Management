1. AUDIT STATUS & OBJECTIVE
-------------------------------------------------------------------------------
Status: Complete — Root cause and exact code breakpoints identified.
Objective:
  Trace the complete student identity verification chain:
  LIFF → LINE OAuth2 → frontend components → NestJS backend → Student identity resolution.
  Identify why attendance submission in production returns:
  `UnauthorizedException: Student authentication required in production environment`

-------------------------------------------------------------------------------
2. CURRENT PRODUCTION SYMPTOM
-------------------------------------------------------------------------------
Flow:
  Student Event → Attendance Button → Active Session (`/attendance/session/[token]`)
  → Student attaches photo proof & recommendation → Click "Submit Attendance"
Error:
  `Student authentication required in production environment` (HTTP 401 Unauthorized)

-------------------------------------------------------------------------------
3. LIFF INITIALIZATION FLOW
-------------------------------------------------------------------------------
File: `apps/web/src/lib/liff.ts`
- `initLiff()` reads `process.env.NEXT_PUBLIC_LIFF_ID`.
- Dynamically imports `@line/liff` SDK on client browser mount.
- Calls `liff.init({ liffId })`.
- Checks `liff.isLoggedIn()`. If true, fetches `idToken` using `liff.getIDToken()`.
- Component: `apps/web/src/components/attendance/StudentAttendanceForm.tsx`
  Calls `initLiff()` inside a `useEffect` hook on mount.
- Login Trigger: If `liff.isLoggedIn()` is false, `triggerLiffLogin()` can call `liff.login()`,
  but current page load does NOT force an automatic redirect to LINE login unless explicitly triggered.

-------------------------------------------------------------------------------
4. ATTENDANCE PAGE AUTHENTICATION FLOW
-------------------------------------------------------------------------------
File: `apps/web/src/components/attendance/StudentAttendanceForm.tsx`
1. Page loads `/attendance/session/[token]`.
2. `useEffect` invokes `initLiff()`.
3. If `state.idToken` exists, `StudentAttendanceForm` calls `verifyLineToken(state.idToken)`.
4. `verifyLineToken()` posts to backend `POST /api/line/verify-token`.
5. Backend verifies token with LINE platform OAuth2 API and returns:
   `{ status: 'LINKED', student: { ... }, accessToken: "eyJhbG..." }`.
6. Frontend updates state `profile = verified.student` and `lineLinked = true`.
7. **GAP IDENTIFIED:** The application JWT `accessToken` returned by `POST /api/line/verify-token` is **never stored** (e.g. in `localStorage` or component state) and **never passed** to subsequent submission requests.

-------------------------------------------------------------------------------
5. FRONTEND API FLOW
-------------------------------------------------------------------------------
File: `apps/web/src/lib/attendance-api.ts` -> `submitAttendance()`
1. Form calls `submitAttendance(token, photoFile, feedback, selectedDevStudentId || profile?.id)`.
2. `submitAttendance` constructs a `FormData` object containing `photo` and `feedback`.
3. Header construction:
   ```ts
   const headers: Record<string, string> = {};
   if (devStudentId) {
     headers['x-dev-student-id'] = devStudentId;
   }
   ```
4. Posts to `POST /api/attendance/sessions/${token}/submit`.
5. **GAP IDENTIFIED:** The request headers contain ONLY `x-dev-student-id`. The frontend does NOT attach `Authorization: Bearer <accessToken>` or any LINE ID Token / authentication header.

-------------------------------------------------------------------------------
6. BACKEND LINE VERIFICATION FLOW
-------------------------------------------------------------------------------
Files: `apps/api/src/line/line.controller.ts` & `apps/api/src/line/line.service.ts`
1. `POST /api/line/verify-token` receives `{ idToken }`.
2. `LineService.verifyIdToken(idToken)` sends HTTP POST to LINE OAuth2 API:
   `https://api.line.me/oauth2/v2.1/verify` (with `id_token` and `client_id`).
3. Extracts `claims.sub` (`lineUserId`).
4. Queries database: `prisma.student.findUnique({ where: { lineUserId } })`.
5. If linked:
   - Signs application JWT `accessToken` payload: `{ sub: student.id, studentId: student.studentId, lineUserId, role: 'STUDENT' }`.
   - Returns `{ status: 'LINKED', lineUserId, student, accessToken }`.

-------------------------------------------------------------------------------
7. ATTENDANCE `resolveStudent()` REQUIREMENTS
-------------------------------------------------------------------------------
File: `apps/api/src/attendance/attendance.service.ts` -> `resolveStudent()`
Signature: `async resolveStudent(studentIdOrParam?: string, lineUserId?: string): Promise<Student>`

Execution Paths:
1. If `lineUserId` is supplied: Looks up student by `lineUserId`.
2. If `NODE_ENV === 'development'`: Accepts `x-dev-student-id` header/parameter, or falls back to `prisma.student.findFirst()`.
3. If `NODE_ENV === 'production'`: `isDev` is `false`. Dev headers/parameters are ignored. Because `lineUserId` was not passed, execution reaches line 215:
   `throw new UnauthorizedException('Student authentication required in production environment');`

10. STUDENT / LINE ACCOUNT LINKING BEHAVIOR
-------------------------------------------------------------------------------
1. Default Seed Data: Seeded production student records have `lineUserId = null`.
2. Account Linking API: `POST /api/line/link-student` accepts `{ idToken, studentId }`.
3. Verifies `idToken` against LINE platform, extracts `lineUserId`, and updates `Student.lineUserId`.
4. Without completing account linking, a student's LINE account returns `status: 'UNLINKED'`.

11. EXACT AUTHENTICATION BREAKPOINTS IDENTIFIED
-------------------------------------------------------------------------------
PRIMARY BREAKPOINT A — BACKEND SUBMISSION CONTROLLER CONTRACT GAP:
  - File: `apps/api/src/attendance/attendance.controller.ts`
  - Method: `submitAttendance()` (Line 89) accepts ONLY `@Param('token')`, `@UploadedFile() file`, `@Body('feedback')`, and `@Headers('x-dev-student-id')`.
  - It does NOT accept `@Headers('authorization')` or `@Headers('x-line-id-token')`.
  - It passes `devStudentId` to `this.attendanceService.submitAttendance(token, devStudentId, file, feedback)`, leaving `lineUserId` undefined.

PRIMARY BREAKPOINT B — BACKEND SERVICE identity RESOLUTION GAP:
  - File: `apps/api/src/attendance/attendance.service.ts`
  - Method: `submitAttendance()` (Line 292) calls `const student = await this.resolveStudent(studentIdOrParam);` without passing `lineUserId`.
  - In production (`isDev = false`), `resolveStudent` ignores `studentIdOrParam` and throws `UnauthorizedException('Student authentication required in production environment')`.

PRIMARY BREAKPOINT C — FRONTEND SUBMISSION TRANSPORT GAP:
  - File: `apps/web/src/lib/attendance-api.ts`
  - Function: `submitAttendance()` (Line 176) sends ONLY `x-dev-student-id`.
  - It does NOT attach `Authorization: Bearer <accessToken>` or a verified LINE ID Token header.

SECONDARY BREAKPOINT D — UNLINKED PRODUCTION ACCOUNTS:
  - Seeded database students have `lineUserId = null`. Until a student clicks "Link LINE Account" (or is linked), verification returns `status: 'UNLINKED'`.

13. RECOMMENDED MINIMAL FIX (FOR NEXT IMPLEMENTATION PHASE)
-------------------------------------------------------------------------------
1. Backend (`AttendanceController` & `AttendanceService`):
   - Update `AttendanceController.submitAttendance` to extract `Authorization` bearer token or `x-line-id-token` header.
   - Decode JWT (or verify LINE token) to extract `sub` (`student.id`) or `lineUserId`.
   - Pass resolved student ID / lineUserId into `resolveStudent()` or query student directly.

2. Frontend (`attendance-api.ts` & `StudentAttendanceForm.tsx`):
   - Store the student JWT `accessToken` returned by `verifyLineToken()` (or `linkStudentAccount()`).
   - Attach `Authorization: Bearer <accessToken>` in `submitAttendance()`.
