1. PHASE NAME & OBJECTIVE
-------------------------------------------------------------------------------
Phase: Phase 16.8 — Student Authentication Bridge (LINE/LIFF → Application JWT)
Objective:
  Bridge the student authentication chain between LINE/LIFF identity verification,
  application JWT token issuance, and server-side attendance submission.
  Ensure production attendance requests send `Authorization: Bearer <application-jwt>`
  and that `resolveStudent()` authoritatively extracts the authenticated Student record
  without allowing student spoofing.

-------------------------------------------------------------------------------
2. PROBLEM FOUND & ROOT CAUSE
-------------------------------------------------------------------------------
Problem:
  In production, submitting attendance returned:
  `UnauthorizedException: Student authentication required in production environment`

Root Cause:
  1. `POST /api/line/verify-token` verified LINE ID tokens and issued application JWTs,
     but the frontend `StudentAttendanceForm` did not persist or attach the JWT.
  2. Frontend `submitAttendance()` in `attendance-api.ts` sent only `x-dev-student-id`.
  3. Backend `AttendanceController.submitAttendance` did not accept or pass `Authorization` bearer headers.
  4. Backend `resolveStudent()` received `lineUserId = undefined`, and since `NODE_ENV === 'production'`
     disabled development headers, `resolveStudent()` threw `UnauthorizedException`.

-------------------------------------------------------------------------------
4. EXACT AUTHENTICATION FLOW BEFORE / AFTER
-------------------------------------------------------------------------------
BEFORE:
  LINE LIFF → `POST /api/line/verify-token` → JWT issued → (JWT dropped by frontend)
  → `submitAttendance()` (sends only `x-dev-student-id`) → Backend `resolveStudent()`
  → `NODE_ENV === 'production'` rejects dev header → `UnauthorizedException` 401.

AFTER:
  LINE LIFF → `POST /api/line/verify-token` → JWT issued
  → Frontend stores JWT in `localStorage.setItem('student_access_token', token)`
  → `submitAttendance()` attaches `Authorization: Bearer <token>`
  → Backend `AttendanceController` receives Authorization header
  → Backend `AttendanceService.resolveStudent()` verifies JWT via `jwtService.verify(token)`
  → Resolves authoritative `Student` from DB by JWT `sub`
  → Attendance record created/updated safely for authenticated student.

-------------------------------------------------------------------------------
5. SECURITY & SPOOFING PROTECTION
-------------------------------------------------------------------------------
- Server-Side Authoritative Identity:
  The backend resolves student identity strictly from the verified JWT `sub` (`Student.id`).
- Student Spoofing Prevention:
  Attempting to modify request body fields or headers to impersonate another student ID is ignored;
  the backend uses ONLY the verified JWT payload identity.
- Production Security:
  `x-dev-student-id` header is strictly ignored when `NODE_ENV === 'production'`.
