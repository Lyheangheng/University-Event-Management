1. OBJECTIVE
--------------------------------------------------------------------------------
Implement Event Banner Image Upload functionality for the University Event Management System.
Allows admins to upload event banners directly from their computer/device to Cloudflare R2 object storage (or local storage in dev), preview the image before saving, replace or remove existing banners, and render banner images across public/student/admin event views while preserving full backward compatibility for existing event image URLs.

- Banners are stored under subfolder `'banners'` (e.g. `banners/1727254400000-<hash>.jpg`), keeping them separated from attendance proof photos (`proofs/`).
- Attendance proof storage and security behavior were left 100% untouched.

4. BACKEND UPLOAD ENDPOINTS
--------------------------------------------------------------------------------
- `POST /api/events/upload-banner`
  - Auth: Admin JWT required (`@UseGuards(JwtAuthGuard, RolesGuard)`, `@Roles('ADMIN')`)
  - Payload: multipart/form-data with `file`
  - Max Size: 5 MB
  - Allowed MIME Types: `image/jpeg`, `image/jpg`, `image/png`, `image/webp`
  - Output: `{ url: string, filename: string }`

- `POST /api/events/:id/banner`
  - Auth: Admin JWT required
  - Uploads file and updates `imageUrl` field on event `:id`, cleaning up any previous storage banner file.

- `DELETE /api/events/:id/banner`
  - Auth: Admin JWT required
  - Removes banner from event `:id`, setting `imageUrl: null` and deleting object from storage.

- `GET /api/events/uploads/banners/:filename` & `GET /api/attendance/uploads/banners/:filename`
  - Auth: Public (No JWT required)
  - Safely streams banner file with `Cache-Control: public, max-age=31536000, immutable`.

5. STORAGE BEHAVIOR
--------------------------------------------------------------------------------
- Subfolder: `banners`
- Filename pattern: `<timestamp>-<16-byte-hex>.<ext>`
- Local Storage: Saved to `uploads/banners/` directory.
- Production S3 / Cloudflare R2: Uploaded to `S3_BUCKET` under key `banners/<filename>`.
- Object Deletion: Replaced or deleted banner objects are cleaned up via `storageService.deleteFile(filename, 'banners')`.

8. SECURITY CHECKS
--------------------------------------------------------------------------------
- Admin authentication required for banner upload, replacement, and deletion (`JwtAuthGuard`, `RolesGuard('ADMIN')`).
- Unauthenticated users and students are strictly blocked from uploading or deleting banner files.
- Strict MIME type whitelist (`image/jpeg`, `image/jpg`, `image/png`, `image/webp`).
- Strict 5MB file size limit enforced server-side and client-side.
- Server-side filename generation using cryptographically secure random bytes; original client filenames are discarded.
- Strict path traversal prevention using `extractAndSanitizeFilename()`; rejects `..`, `%`, `\`, null bytes, and path tricks.
- Public banner endpoint only permits streaming files from the `banners` subfolder.

9. BACKWARD COMPATIBILITY
--------------------------------------------------------------------------------
- Existing production events with external image URLs (e.g. `https://images.unsplash.com/...`) remain 100% functional.
- The system gracefully handles external URLs, uploaded R2/local banners, and null image URLs.
