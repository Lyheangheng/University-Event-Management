PHASE 16.25 — EVENT GALLERY + EVENT IMAGE DISPLAY FIX REPORT
================================================================================

1. OBJECTIVE
--------------------------------------------------------------------------------
Phase 16.25 resolves the production event banner rendering failure and introduces
multi-photo event gallery support. Admin users can optionally upload a banner image
and/or multiple event gallery photos. Public and student users can view full-res
event photos in a responsive gallery grid with lightbox modal previews on the event
detail page.

2. ROOT CAUSE OF PHASE 16.24 BANNER DISPLAY BUG
--------------------------------------------------------------------------------
"Banner display failed because uploaded Cloudflare R2 object URLs 
(https://<account-id>.r2.cloudflarestorage.com/...) require AWS SigV4 authentication
headers for direct HTTP GET access, causing unauthenticated browser <img src="..."> 
requests to fail with HTTP 401/403. Furthermore, relative local endpoint paths 
(e.g., /api/events/uploads/banners/...) rendered on Vercel frontend resolved 
relative to the Vercel domain instead of the NestJS Render backend server, causing 
HTTP 404 Not Found."

3. BANNER FIX
--------------------------------------------------------------------------------
- Standardized image URL resolution via `getEventImageUrl` helper in `formatters.ts`.
- Relative backend streaming paths (`/api/events/uploads/banners/...`) are automatically
  prepended with the backend API base URL (`NEXT_PUBLIC_API_URL`) when rendered on the frontend.
- `S3StorageProvider` and `LocalStorageProvider` format public URLs to route through
  the public backend streaming endpoint `GET /api/events/uploads/banners/:filename`.
- Unauthenticated browser `<img src="...">` requests succeed with HTTP 200 and correct
  `Content-Type` without exposing R2 AWS credentials or making the R2 bucket public.

4. EVENTIMAGE DATABASE DESIGN
--------------------------------------------------------------------------------
Added `EventImage` model and `images EventImage[]` relation to `prisma/schema.prisma`:

model EventImage {
  id         String   @id @default(uuid())
  eventId    String
  storageKey String
  imageUrl   String
  sortOrder  Int      @default(0)
  createdAt  DateTime @default(now())

  event Event @relation(fields: [eventId], references: [id], onDelete: Cascade)

  @@index([eventId])
  @@index([eventId, sortOrder])
}

- Cascading deletion: `onDelete: Cascade` ensures deleting an `Event` automatically
  removes associated `EventImage` database records.

5. MIGRATION

6. STORAGE DESIGN
--------------------------------------------------------------------------------
- Reused existing `S3StorageProvider` (Cloudflare R2) and `LocalStorageProvider`.
- Isolated storage folder namespace: `event-images/` (e.g. `event-images/<unique-filename>`).
- Safe filename generation using server-generated unique prefixes and sanitized basenames.
- Storage credentials remain strictly server-side in NestJS backend.

7. API ENDPOINTS
--------------------------------------------------------------------------------
- `POST /api/events/:id/images` (Admin JWT required)
  Upload single or multiple gallery photos for an event. Preserves upload order.
- `GET /api/events/:id/images` (Public)
  Retrieve list of `EventImage` objects sorted by `sortOrder`.
- `DELETE /api/events/:id/images/:imageId` (Admin JWT required)
  Deletes `EventImage` database record and purges R2 storage object.
- `GET /api/events/uploads/event-images/:filename` (Public Streaming)
  Safely streams gallery photo from R2/LocalStorage with traversal guards and cache headers.

8. ADMIN UX
--------------------------------------------------------------------------------
- Create Event (`/admin/events/new`):
  - Optional banner upload with preview and removal.
  - Multi-photo gallery selection with instant local previews and individual removal.
- Edit Event (`/admin/events/[id]/edit`):
  - Display existing banner with Replace/Remove controls.
  - Display existing gallery photos with individual Delete buttons (triggers instant API delete & R2 purge).
  - Add new gallery photos with local previews before saving.

9. PUBLIC / STUDENT UX
--------------------------------------------------------------------------------
- `EventCard`:
  - Thumbnail order: Banner image -> First Gallery photo -> Fallback UI gradient badge.
  - Banner is completely optional.
- Event Detail (`/events/[id]`):
  - Displays banner image if available.
  - Displays responsive Photo Gallery Grid (3 columns on desktop, 2 on mobile).
  - Lightbox Preview Modal on photo click with full-screen view and image counter.

10. SECURITY
--------------------------------------------------------------------------------
- Admin JWT required for gallery upload and image deletion endpoints.
- Path traversal protection via `extractAndSanitizeFilename` (rejects `../`, `%2f`, null bytes).
- MIME validation restricted strictly to `image/jpeg`, `image/png`, `image/webp`.
- File size capped at 5 MB per image.
- R2 credentials never exposed to browser context.
