4. AUTHENTICATION HARDENING
--------------------------------------------------------------------------------
- Passwords: Admin passwords stored exclusively as `bcryptjs` hashes.
- JWT Verification: Validates algorithm signature, expiration (`ignoreExpiration: false`), and `sub`/`role` claims via Passport JWT strategy.
- Development Header Scoping: The header fallback `x-dev-student-id` is strictly enabled ONLY when `NODE_ENV === 'development'`. In production (`NODE_ENV === 'production'`), header bypass is disabled and requires verified student JWT authentication.

5. AUTHORIZATION / IDOR PROTECTION
--------------------------------------------------------------------------------
- Admin Routes: All admin-only routes (`/api/auth/admin/me`, `/api/events` mutations, `/api/events/:eventId/attendance`) strictly require `@UseGuards(JwtAuthGuard, RolesGuard)` and `@Roles('ADMIN')`.
- Student Profile: `GET /api/attendance/me` returns only the authenticated student identity.
- Attendance Submission: Attendance check-in and check-out records are bound strictly to the authenticated student ID. Clients cannot submit another student's record.

6. INPUT VALIDATION
--------------------------------------------------------------------------------
- Global `ValidationPipe` configured with `whitelist: true`, `forbidNonWhitelisted: true`, and `transform: true`.
- LINE endpoints enforce `LineVerifyTokenDto` and `LineLinkStudentDto`.
- Event creation/update enforces `@MaxLength(200)` for title and location, `@MaxLength(100)` for target group, and `@MaxLength(5000)` for description.

7. EVENT VALIDATION
--------------------------------------------------------------------------------
- Server enforces `startTime < endTime`.
- Dates and timestamps validated against ISO 8601 standard.
- Image URLs validated via `@IsUrl()`.

8. ATTENDANCE VALIDATION
--------------------------------------------------------------------------------
- Enforces lifecycle: `CHECK_IN` (status `INCOMPLETE`) -> `CHECK_OUT` (status `COMPLETED`).
- Rejects duplicate check-ins ("Check-in has already been recorded...").
- Rejects check-out without prior check-in ("Check-in record not found...").
- Rejects duplicate check-outs ("Check-out has already been recorded...").
- Feedback length capped at 1000 characters with whitespace trimming.

9. QR / SESSION SECURITY
--------------------------------------------------------------------------------
- Attendance session tokens generated using `crypto.randomBytes(32).toString('hex')`.
- Tokens contain no student PII or sequential IDs.
- Validated using authoritative server clock (`startTime <= serverNow < endTime`).
- Invalid or expired tokens return HTTP 404 or 400.

10. FILE UPLOAD SECURITY
--------------------------------------------------------------------------------
- Strictly JPEG, PNG, and WebP only.
- 5 MB maximum file size limit.
- Server-generated unguessable filenames (`crypto.randomBytes`).
- Path traversal prevention (`path.basename` and root directory boundary checks).
- Content-Type headers enforced. No client path exposure.

11. LINE / LIFF SECURITY
--------------------------------------------------------------------------------
- Official Token Verification: Backend verifies ID tokens directly via `https://api.line.me/oauth2/v2.1/verify`.
- Webhook Verification: Enforces `x-line-signature` header check using HMAC-SHA256 with `LINE_CHANNEL_SECRET`.
- Channel secret and channel access tokens kept backend-only.

12. ENVIRONMENT / SECRET SECURITY
--------------------------------------------------------------------------------
- `.env` ignored by Git (`.gitignore`).
- No plain passwords, secrets, or database credentials hardcoded in codebase.
- `.env.example` contains placeholders only.

13. CORS / HTTP SECURITY
--------------------------------------------------------------------------------
- CORS restricted to `configService.get('frontendUrl')` and `http://localhost:3000` with `credentials: true`.

14. ERROR RESPONSE SECURITY

15. RATE LIMITING DECISION
