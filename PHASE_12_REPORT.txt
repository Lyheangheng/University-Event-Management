5. STORAGE ABSTRACTION
--------------------------------------------------------------------------------
The application now uses a clean `StorageService` abstraction in NestJS.
- `StorageProvider` Interface: Defines contract (`save`, `getFilePath`, `delete`, `getPublicUrl`).
- `StorageService`: Injected across NestJS modules. Delegates storage calls to the active provider specified by `STORAGE_PROVIDER` configuration.
- Allows replacing `LocalStorageProvider` with an object storage provider (e.g. S3, Cloudinary) without rewriting attendance services or controllers.

6. LOCAL STORAGE IMPLEMENTATION
--------------------------------------------------------------------------------
- Default provider: `LocalStorageProvider`.
- Dedicated storage directory: `apps/api/uploads/proofs/` (outside `src/`, Git-ignored).
- Generates server-side filenames using timestamp + 16 random crypto hex bytes + sanitized extension (e.g., `1774310719-a1b2c3d4e5f67890.jpg`).
- Never trusts client-supplied original filenames.

7. UPLOAD VALIDATION
--------------------------------------------------------------------------------
- Allowed MIME Types: `image/jpeg`, `image/jpg`, `image/png`, `image/webp`.
- Rejected MIME Types: All non-image files (e.g., `text/plain`, `application/pdf`, `image/gif`) throw `BadRequestException`.
- Size Limit: 5 MB (`5 * 1024 * 1024` bytes). Exceeding uploads throw `BadRequestException`.
- Malformed/Empty Files: Buffer check ensures file is non-empty.

8. SAFE FILE SERVING
--------------------------------------------------------------------------------
- Endpoint: `GET /api/attendance/uploads/proofs/:filename`
- `StorageService.getFilePath` sanitizes requested filename using `path.basename`.
- Rejects requests containing directory traversal attempts (`..`, `/`, `\`, `%`).
- Verifies that target resolved path is strictly contained within the allowed uploads directory (`filePath.startsWith(targetDir)`).
- Sets explicit `Content-Type` header based on verified extension (`image/jpeg`, `image/png`, `image/webp`).
- Non-existent files return `404 Not Found`.

17. FUTURE PRODUCTION STORAGE CONSIDERATIONS
--------------------------------------------------------------------------------
To switch to cloud object storage (e.g. AWS S3, Google Cloud Storage, Cloudinary):
1. Implement `StorageProvider` interface in `s3-storage.provider.ts`.
2. Configure `STORAGE_PROVIDER=s3` and credentials in `.env`.
3. Update `StorageService` to instantiate `S3StorageProvider` when `providerType === 's3'`.
No changes to attendance controllers or business logic will be needed.
