===============================================================================

OBJECTIVE
-------------------------------------------------------------------------------
Transform the University LINE Official Account (OA) notification experience into a 
visually rich social-media style event post and align the student LIFF event detail 
page (/events/[id]) to be visually consistent with LINE mobile UI guidelines.

EXISTING LINE NOTIFICATION ARCHITECTURE AUDIT (PART 1)
-------------------------------------------------------------------------------
1. Service File: `apps/api/src/line/line-messaging.service.ts`
2. Event Announcement Trigger: `EventsService.createEvent()` in `apps/api/src/events/events.service.ts`
   invokes `LineMessagingService.notifyEventAnnouncement(event)`.
3. Check-In Window Trigger: `AttendanceService.openSession()` / `getSessionByToken()` in
   `apps/api/src/attendance/attendance.service.ts` invokes `LineMessagingService.notifyCheckInOpened()`.
4. Check-Out Window Trigger: `AttendanceService.openSession()` / `getSessionByToken()` in
   `apps/api/src/attendance/attendance.service.ts` invokes `LineMessagingService.notifyCheckOutOpened()`.
5. Idempotency: Managed via `sentNotifications: Set<string>` in `LineMessagingService`.
   `event_announcement_${event.id}`, `check_in_open_${event.id}`, `check_out_open_${event.id}` keys
   prevent duplicate notifications.
6. Environment Variables:
   - `LINE_CHANNEL_ACCESS_TOKEN` / `line.channelAccessToken`
   - `LINE_CHANNEL_SECRET` / `line.channelSecret`
   - `FRONTEND_URL` (Web/LIFF base URL)
   - `BACKEND_URL` / `API_BASE_URL` (Render API base URL)

LINE FLEX MESSAGE DESIGN (PART 2, 3, 5, 6)
-------------------------------------------------------------------------------
- Structure:
  - Hero Image: Uses optional event banner if available; if not available, uses first gallery photo;
    if no image exists, renders a clean green visual badge ("🎓 UNIVERSITY EVENT").
  - Body:
    - Event Title (bold, size xl)
    - Metadata Rows: 📅 Date, 🕘 Time Range, 📍 Location
    - Truncated Description Preview (max 120 chars)
  - Footer:
    - [ View Event ] green primary button pointing to `${FRONTEND_URL}/events/${event.id}`.
  - Activities Carousel (Message 2 in push array):
    - Appears when `EventImage` records exist for the event.
    - Rendered as a LINE Flex Carousel with micro photo bubbles.
    - Capped at maximum 12 bubbles (if >12 photos, 11 photo bubbles + "+N More / View All Photos" bubble).
  - Notification Alt Text:
    - Compact text summary with title, date, time, location, and tap prompt for non-visual preview environments.

IMAGE URL STRATEGY (PART 4 & 9)
-------------------------------------------------------------------------------
- Image Priority:
  1. Optional event banner (`event.imageUrl`)
  2. First gallery image (`event.images[0].imageUrl`)
  3. Fallback UI badge
- Streaming Endpoints:
  - Banners: `GET /api/events/uploads/banners/:filename`
  - Gallery Photos: `GET /api/events/uploads/event-images/:filename`
- Resolution: All stored relative paths or R2 keys are converted to complete HTTPS URLs:
  e.g., `https://university-event-api.onrender.com/api/events/uploads/event-images/...`
- No Cloudflare R2 credentials or raw bucket endpoints are exposed to clients or LINE payloads.
