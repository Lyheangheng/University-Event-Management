7. TIMING BOUNDARY TESTS
------------------------------------------------------------------------------
- Backend Authority: Server clock is the sole authority; client clock/countdown cannot override backend bounds.
- timing Operator Implementation:
  - Window calculation code: `const isOpen = serverNow >= windowStart && serverNow <= windowEnd;`
  - Inclusive boundary check: Uses `>=` for window start and `<=` for window end.
- CHECK_IN Bounds:
  - windowStart = event.startTime
  - windowEnd = event.startTime + 30 minutes
- CHECK_OUT Bounds:
  - windowStart = event.endTime - 30 minutes
  - windowEnd = event.endTime + 30 minutes
- Overlap Window: During the final 30 minutes of event (if event duration <= 60 mins), both CHECK_IN and CHECK_OUT can be valid simultaneously if timing ranges overlap.

9. AUTHENTICATION & SECURITY TESTS
------------------------------------------------------------------------------
- Cross-Type Session Abuse:
  - CHECK_IN token supplied for check-out -> Evaluated against CHECK_IN session type logic; duplicate/window rules enforced.
  - Token from Event A used for Event B -> Token lookup retrieves target event bound in DB; student cannot alter event ID.
  - Expired / Invalid token -> HTTP 404 ("Attendance session not found or invalid token") or HTTP 400 ("Check-in is not currently open").
- Header & Secret Security:
  - Missing Authorization header -> HTTP 401 Unauthorized in production.
  - Invalid / Expired JWT -> HTTP 401 Unauthorized.
  - Student JWT attempting Admin endpoints -> HTTP 403 Forbidden (RolesGuard `@Roles('ADMIN')`).
  - `x-dev-student-id` header bypass attempt -> HTTP 401 Unauthorized in production environment (`isDev=false`).
