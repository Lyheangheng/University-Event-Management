6. DATABASE CHANGES:
   None. Reused existing Attendance model from Phase 1 Prisma schema:
   - id (UUID)
   - studentId (Foreign Key to Student)
   - eventId (Foreign Key to Event)
   - checkInTime (DateTime?)
   - checkInProofUrl (String?)
   - checkOutTime (DateTime?)
   - checkOutProofUrl (String?)
   - feedback (String?)
   - status (Enum: INCOMPLETE | COMPLETED)
   - @@unique([studentId, eventId])

7. STUDENT IDENTITY / AUTHENTICATION APPROACH:
   - Backend derives student identity strictly from authentication (`req.user.userId` via JWT or development header `x-dev-student-id`).
   - Client-submitted identity fields (fullName, studentId, year, faculty, major) are displayed read-only on the frontend and are NOT accepted or trusted from the client payload.

8. ATTENDANCE FORM FIELDS:
   - Event Header: Title, Date, Time Range, Location.
   - Session Status Badge: `CHECK-IN SESSION` or `CHECK-OUT SESSION`.
   - Read-Only Student Profile: Full Name, Student ID, Faculty, Major, Year.
   - Photo Proof Input: File selector/camera capture with live preview, 5MB size limit check, and "Replace Photo" option.
   - Recommendation / Feedback Input: Optional text area (max 1000 characters).
   - Double-Submit Protected Button: Disables on submit with loading spinner.

9. PHOTO HANDLING APPROACH:
   - Uploaded photo proofs are stored locally under `uploads/proofs/` outside source control (`.gitignore`).
   - Safe filenames generated via `Date.now()` + random crypto hex bytes to prevent path traversal and collision.
   - Validates image MIME type (`image/jpeg`, `image/png`, `image/webp`) and 5MB size limit.
   - Served via static endpoint `GET /api/attendance/uploads/proofs/:filename`.

10. RECOMMENDATION / FEEDBACK HANDLING:
    - Textarea for optional student feedback.
    - Server-side validation trims whitespace and enforces a 1000 character maximum length limit.

11. CHECK_IN BEHAVIOR:
    - Records `checkInTime = serverNow`, `checkInProofUrl`, `status = INCOMPLETE`.
    - If student has already checked in for the event, backend rejects with "Check-in has already been recorded for this event".

12. CHECK_OUT BEHAVIOR:
    - Updates existing attendance record with `checkOutTime = serverNow`, `checkOutProofUrl`, `status = COMPLETED`.
    - Rejects if check-in record does not exist ("Check-in record not found. You must check in before checking out.") or if student already checked out.

13. ATTENDANCE STATUS BEHAVIOR:
    - Uses Prisma `AttendanceStatus` enum.
    - `CHECK_IN` sets status to `INCOMPLETE`.
    - `CHECK_OUT` updates status to `COMPLETED`.

14. API ENDPOINTS:
    - GET /api/attendance/me: Returns current student profile details.
    - POST /api/attendance/sessions/:token/submit: Processes multipart/form-data attendance submission.
    - GET /api/attendance/uploads/proofs/:filename: Serves saved proof photos safely.

15. SESSION VALIDATION:
    - Strictly validates `startsAt <= serverNow < endsAt` using server clock authority.

16. DUPLICATE-SUBMISSION PROTECTION:
    - Client disables submit button while `submitting` is true.
    - Backend relies on Prisma `@@unique([studentId, eventId])` constraint and explicit checkInTime/checkOutTime presence checks.

17. SECURITY VALIDATION:
    - Server time is authoritative.
    - Client identity fields are ignored.
    - Image MIME types and sizes are checked.
    - Path traversal is prevented on file serving.
