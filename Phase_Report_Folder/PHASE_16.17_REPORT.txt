4. EVENT ANNOUNCEMENT TRIGGER
- Triggered immediately after `prisma.event.create()` succeeds in `EventsService.createEvent()`.
- Calls existing `LineMessagingService.notifyEventAnnouncement(event)`.
- Sends formatted LINE push message containing title, date, time range, location, and event details URL (`/events/:id`) to all linked students.

5. CHECK_IN NOTIFICATION TRIGGER
- Triggered when a `CHECK_IN` session is activated/created in `AttendanceService.getActiveSession()`.
- Calls existing `LineMessagingService.notifyCheckInOpened(event, newSession.token)`.
- Sends formatted LINE push message containing event title and direct session form URL (`/attendance/session/:token`) to all linked students.

6. CHECK_OUT NOTIFICATION TRIGGER
- Triggered when a `CHECK_OUT` session is activated/created in `AttendanceService.getActiveSession()`.
- Calls existing `LineMessagingService.notifyCheckOutOpened(event, newSession.token)`.
- Sends formatted LINE push message containing event title and direct session completion URL (`/attendance/session/:token`) to all linked students.

7. NOTIFICATION TARGETING
- Target audience: All student records where `lineUserId` is not null (`Student.lineUserId != null`).
- Unlinked students or students without a LINE account linked through LIFF are safely skipped.

8. IDEMPOTENCY APPROACH
- Process-level deduplication tracking in `LineMessagingService` using keys:
  - Event announcement: `event_announcement_${event.id}`
  - Check-in notification: `check_in_open_${event.id}`
  - Check-out notification: `check_out_open_${event.id}`
- Lifecycle-level deduplication in `AttendanceService.getActiveSession()`: Existing active sessions retrieved from DB skip creation, preventing repeated triggers on routine session lookups.
- No database schema changes were required.

9. ERROR HANDLING
- Notification calls inside `createEvent` and `getActiveSession` are wrapped in `try/catch` blocks.
- If LINE push API fails or Channel Access Token is missing, server logs the error (`this.logger.error`) but event creation and attendance session creation proceed successfully.
- No secrets, tokens, or private credentials are exposed in logs.
