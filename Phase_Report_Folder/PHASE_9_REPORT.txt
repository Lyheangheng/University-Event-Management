1. PHASE GOAL
--------------------------------------------------------------------------------
Refine and complete the end-to-end student attendance lifecycle:
CHECK_IN -> INCOMPLETE -> CHECK_OUT -> COMPLETED

Ensure authoritative server-side time validation, single Attendance record per student/event, 
seamless UI state presentation across all 4 attendance states, and clean projector display 
state machine transitions without introducing any breaking changes or schema alterations.

4. BACKEND CHANGES
--------------------------------------------------------------------------------
- Updated `getSessionByToken(token: string, studentIdOrParam?: string)` in `AttendanceService` 
  to resolve the current student identity and attach `existingAttendance` record details 
  (`id`, `checkInTime`, `checkInProofUrl`, `checkOutTime`, `checkOutProofUrl`, `feedback`, `status`).
- Added `@Headers('x-dev-student-id')` parameter passing to `getSessionByToken` in `AttendanceController`.
- Enforced strict backend error responses:
  * Check-out without prior check-in -> 400 Bad Request ("Check-in record not found. You must check in before checking out.")
  * Duplicate check-out submission -> 400 Bad Request ("Check-out has already been recorded for this event")
  * Duplicate check-in submission -> 400 Bad Request ("Check-in has already been recorded for this event")
  * Inactive or expired session token -> 400 Bad Request ("Attendance session has expired or is not yet active")
  * Invalid token -> 404 Not Found ("Attendance session not found or invalid token")

5. FRONTEND CHANGES
--------------------------------------------------------------------------------
- Updated `SessionValidationData` interface in `attendance-api.ts` to support optional `existingAttendance` payload.
- Forwarded `x-dev-student-id` header in `fetchSessionByToken` for local development testing.
- Refined `StudentAttendanceForm.tsx` to handle 4 distinct attendance lifecycle UI states:
  1. Not Checked In (Check-in Session): Shows check-in form, photo proof upload, and feedback.
  2. Checked In / Waiting for Checkout (Check-in Session when already checked in): Shows Check-in timestamp, 
     status INCOMPLETE, and informational message explaining checkout opens during final 15 minutes of event.
  3. Checkout Available (Check-out Session): Shows Check-In time badge, checkout photo proof upload, 
     and submit check-out button (or warning card if student attempts checkout without prior check-in).
  4. Attendance Completed: Shows Attendance Completed card with Check-In time, Check-Out time, 
     status COMPLETED, and confirmation details.

6. CHECKOUT STATE FLOW
--------------------------------------------------------------------------------
The complete attendance state lifecycle operates as follows:
[Student Scans CHECK-IN QR] -> Check-In Form Submitted
  └─> Server sets `checkInTime` = serverNow, `checkInProofUrl`, `status` = INCOMPLETE
[Projector Transitions to CHECK_OUT_WINDOW] -> Student Scans CHECK-OUT QR
  └─> Server verifies existing Check-In record exists
  └─> Server updates `checkOutTime` = serverNow, `checkOutProofUrl`, `status` = COMPLETED
  └─> Preserves original `checkInTime`, `checkInProofUrl`, and appends optional feedback.

8. SECURITY CONSIDERATIONS
--------------------------------------------------------------------------------
- Session tokens are cryptographically generated random strings (`crypto.randomBytes(32).toString('hex')`).
- Tokens contain NO student identity or PII.
- Server time (`serverNow`) is strictly authoritative for window comparisons and timestamps.
- Photo proof uploads are validated for image mime-type and 5MB size limit.
