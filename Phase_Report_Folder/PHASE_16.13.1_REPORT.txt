1. Phase:
   Phase 16.13.1 — Production JWT Secret Security Correction

2. Security Correction:
   - Enforced strict production validation for `JWT_SECRET`.
   - The development fallback secret (`dev-secret-key-university-event-system`) 
     is now **strictly forbidden** when `NODE_ENV === 'production'`.
   - In production mode, if `JWT_SECRET` is missing, unconfigured, or set to the 
     development fallback secret, the application configuration throws a critical 
     security exception during startup instead of silently falling back to dev credentials.
   - Development mode retains the existing fallback for convenience during local testing.
   - All modules (`LineModule`, `AttendanceModule`, `AuthModule`, `JwtStrategy`, `configuration.ts`) 
     now resolve the JWT secret using the centralized `getRequiredJwtSecret` helper.

3. Files Changed:
   - `apps/api/src/config/jwt-secret.helper.ts` (CREATED): Shared helper enforcing explicit `JWT_SECRET` in production mode.
   - `apps/api/src/config/configuration.ts`: Added production configuration validation throwing an error if `JWT_SECRET` is missing or default in production.
   - `apps/api/src/line/line.module.ts`: Updated to use `getRequiredJwtSecret`.
   - `apps/api/src/attendance/attendance.module.ts`: Updated to use `getRequiredJwtSecret`.
   - `apps/api/src/auth/auth.module.ts`: Updated to use `getRequiredJwtSecret`.
   - `apps/api/src/auth/strategies/jwt.strategy.ts`: Updated to use `getRequiredJwtSecret`.
   - `apps/api/src/attendance/attendance-regression.spec.ts`: Added Test 7 validating that missing or dev `JWT_SECRET` throws a critical security error in production mode while allowing dev fallback in development mode.
