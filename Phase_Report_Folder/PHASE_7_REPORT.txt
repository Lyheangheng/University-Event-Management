6. DATABASE CHANGES:
   None. Reused existing AttendanceSession model from Phase 1 Prisma schema:
   - id (UUID)
   - eventId (String, relation to Event)
   - sessionType (Enum: CHECK_IN | CHECK_OUT)
   - token (String @unique)
   - startTime (DateTime)
   - endTime (DateTime)

7. ATTENDANCESESSION IMPLEMENTATION:
   - Business logic implemented in AttendanceService using PrismaService.
   - Idempotence: Repeated requests during the same active window return the existing session record without re-generating tokens every second.

8. TOKEN GENERATION METHOD:
   - Cryptographically secure 256-bit random tokens generated using Node.js `crypto.randomBytes(32).toString('hex')` (64-character hex string).
   - Unique, difficult to guess, never exposes incremental IDs, database secrets, or raw event IDs.

9. SESSION TIMING RULES:
   - CHECK_IN Session:
     * Starts: event.startTime
     * Ends: event.startTime + 10 minutes
   - CHECK_OUT Session:
     * Starts: event.endTime - 15 minutes
     * Ends: event.endTime
   - Authoritative Validity: Server time (`new Date()`) is strictly enforced (`startTime <= serverNow < endTime`). Client clock state is completely ignored.

10. API ENDPOINTS:
    - GET /api/attendance/events/:eventId/session
      * Returns active session for an event if server time falls into check-in/check-out window. Returns `{ success: true, data: null }` if outside windows.
    - GET /api/attendance/sessions/:token
      * Retrieves and validates an attendance session by token. Throws 404 for invalid tokens and 400 for expired/inactive sessions.

11. QR GENERATION IMPLEMENTATION:
    - Installed `qrcode.react` library in Next.js frontend (`apps/web`).
    - Created `QrCodeDisplay` component utilizing `QRCodeSVG` with high-contrast, scalable 240px SVG rendering.
    - Encodes attendance session URL: `${FRONTEND_URL}/attendance/session/${token}`.

12. PROJECTOR INTEGRATION:
    - Updated `/events/[id]/display` page.
    - Maintains 5-state projector display state machine (`BEFORE_EVENT`, `CHECK_IN_WINDOW`, `BETWEEN_CHECK_IN_AND_CHECKOUT`, `CHECK_OUT_WINDOW`, `ENDED`).
    - Automatically displays real `QrCodeDisplay` during `CHECK_IN_WINDOW` and `CHECK_OUT_WINDOW` when active session is present, falling back to `QrPlaceholder` otherwise.

13. STUDENT SESSION ROUTE:
    - Created `/attendance/session/[token]/page.tsx`.
    - Validates token against backend API upon load.
    - Displays session status (`CHECK-IN SESSION` / `CHECK-OUT SESSION`), event details, session window bounds, and active verification notice.
    - Displays clear error state for expired or invalid tokens.

14. POLLING IMPLEMENTATION:
    - Projector display polls `GET /api/attendance/events/:eventId/session` every 5 seconds during check-in/check-out windows.
    - Countdown ticker updates every 1 second independently.
    - Polling interval is cleanly initialized and destroyed on unmount to prevent duplicate timers and memory leaks.

15. SECURITY MEASURES:
    - Cryptographically secure 64-character hex tokens.
    - Strict server-side time validation.
    - No public POST session creation endpoints exposed.
    - No database credentials or student secrets embedded in QR data.
